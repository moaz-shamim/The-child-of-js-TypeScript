# Enums in TypeScript :

You're learning **enums** in TypeScript. Enums allow you to define a set of named constants.

Your code is almost correct—there is a small syntax error in the `console.log()` statement.

---

## Numeric enums

```ts id="fy9qrf"
enum CupSize {
  SMALL,
  MEDIUM,
  LARGE
}

const size = CupSize.LARGE;
```

By default, TypeScript assigns numbers starting from `0`.

The enum values become:

```ts id="3am9an"
enum CupSize {
  SMALL = 0,
  MEDIUM = 1,
  LARGE = 2
}
```

So:

```ts id="5hqf9v"
console.log(size); // 2
```

You can also do reverse lookup with numeric enums:

```ts id="7ejh4c"
console.log(CupSize[2]); // "LARGE"
```

---

## Numeric enums with custom values

```ts id="ymztnx"
enum Status {
  PENDING = 100,
  SERVED,
  CANCELLED
}
```

After assigning `100` to `PENDING`, TypeScript auto-increments the remaining values.

This becomes:

```ts id="f5yxqu"
enum Status {
  PENDING = 100,
  SERVED = 101,
  CANCELLED = 102
}
```

Example:

```ts id="2l9vwg"
console.log(Status.SERVED); // 101
console.log(Status[102]);   // "CANCELLED"
```

---

## String enums

```ts id="xg8n1v"
enum ChaiType {
  MASALA = "masala",
  GINGER = "ginger"
}
```

String enums require explicit values.

Example:

```ts id="8h6sml"
console.log(ChaiType.MASALA); // "masala"
```

Unlike numeric enums, string enums do not support reverse mapping:

```ts id="lcl00h"
console.log(ChaiType["masala"]); // ❌ undefined
```

---

## Using enums in functions

Your function should be:

```ts id="t1zv7e"
function makeChai(type: ChaiType) {
  console.log(`Making: ${type}`);
}

makeChai(ChaiType.MASALA);
```

Output:

```text id="pqxub6"
Making: masala
```

❌ Invalid:

```ts id="b39kgm"
makeChai("masala");
```

Error:

```text id="8thv8u"
Argument of type '"masala"' is not assignable to parameter of type 'ChaiType'.
```

The function expects a value from the `ChaiType` enum, not a plain string.

---

## Why use enums?

Enums help you:

* Avoid magic values
* Improve autocomplete
* Prevent invalid inputs
* Make code easier to understand

Without enums:

```ts id="bjlwm6"
function makeChai(type: string) {}
```

Anyone could pass:

```ts id="k6mr8g"
makeChai("abc"); // ❌ Allowed
```

With enums:

```ts id="x5x97c"
makeChai(ChaiType.MASALA); // ✅
```

Only valid options are accepted.

---

## Alternative: union types

In modern TypeScript projects, many developers prefer string unions over enums:

```ts id="9avflv"
type ChaiType = "masala" | "ginger";

function makeChai(type: ChaiType) {
  console.log(`Making: ${type}`);
}
```

This avoids the extra JavaScript code generated by enums.

Use:

* `enum` when you need named constants and runtime values.
* Union types when you only need type safety.

---

### Quick summary

| Enum type                       | Example                                 |
| ------------------------------- | --------------------------------------- |
| Numeric enum                    | `enum Size { SMALL, MEDIUM, LARGE }`    |
| Numeric enum with custom values | `enum Status { PENDING = 100, SERVED }` |
| String enum                     | `enum ChaiType { MASALA = "masala" }`   |

# Heterogeneous enums & const enum :

Your examples show two important TypeScript enum concepts:

1. **Heterogeneous enums**
2. **`const enum`**

---

## Heterogeneous enums

```ts id="jklz1x"
enum RandomEnum {
  ID = 1,
  NAME = "chai"
}
```

This enum mixes:

* Numeric values
* String values

Result:

```ts id="9q3d4m"
RandomEnum.ID;   // 1
RandomEnum.NAME; // "chai"
```

While TypeScript allows this, it is generally discouraged because it makes the enum harder to understand and use.

❌ Avoid:

```ts id="tr64qa"
enum RandomEnum {
  ID = 1,
  NAME = "chai"
}
```

✅ Prefer one type consistently:

```ts id="wlr4z8"
enum UserField {
  ID = 1,
  AGE = 2
}
```

or

```ts id="jlwm8u"
enum ChaiType {
  MASALA = "masala",
  GINGER = "ginger"
}
```

Also note that reverse mapping only works for numeric members:

```ts id="js8jhr"
console.log(RandomEnum[1]); // "ID"
```

But:

```ts id="6xevlx"
console.log(RandomEnum["chai"]); // undefined
```

---

## `const enum`

```ts id="c3djnm"
const enum Sugars {
  LOW = 1,
  MEDIUM = 2,
  HIGH = 3
}

const s = Sugars.HIGH;

console.log(s); // 3
```

A `const enum` is completely removed during compilation.

Instead of generating an enum object, TypeScript inlines the value directly.

Your TypeScript:

```ts id="bjlwm6"
const enum Sugars {
  LOW = 1,
  MEDIUM = 2,
  HIGH = 3
}

const s = Sugars.HIGH;
```

Compiles roughly to JavaScript like:

```js id="zzlqxb"
const s = 3;

console.log(s);
```

No enum object exists at runtime.

This improves performance and reduces bundle size.

---

## Normal enum vs `const enum`

Normal enum:

```ts id="lby7zg"
enum Sugars {
  LOW = 1,
  MEDIUM = 2,
  HIGH = 3
}
```

Compiles approximately to:

```js id="l7lm6k"
var Sugars;

(function (Sugars) {
  Sugars[Sugars["LOW"] = 1] = "LOW";
  Sugars[Sugars["MEDIUM"] = 2] = "MEDIUM";
  Sugars[Sugars["HIGH"] = 3] = "HIGH";
})(Sugars || (Sugars = {}));
```

`const enum`:

```ts id="y05yn4"
const enum Sugars {
  LOW = 1,
  MEDIUM = 2,
  HIGH = 3
}
```

Compiles to:

```js id="1ehqk6"
const s = 3;
```

---

## Limitations of `const enum`

Because the enum is erased at compile time, you cannot do runtime operations:

❌ Invalid:

```ts id="l5uln7"
console.log(Sugars);
```

❌ Invalid:

```ts id="jy1lnx"
console.log(Sugars[3]);
```

There is no `Sugars` object in the generated JavaScript.

Use a normal enum if you need:

* Reverse mapping
* Iteration
* Runtime access

Use `const enum` if you only need compile-time constants.

---

## Quick summary

| Feature                     | `enum`           | `const enum` |
| --------------------------- | ---------------- | ------------ |
| Exists at runtime           | ✅                | ❌            |
| Generates JavaScript object | ✅                | ❌            |
| Reverse mapping             | ✅ (numeric only) | ❌            |
| Smaller bundle size         | ❌                | ✅            |
| Better performance          | ❌                | ✅            |

### Best practices

* Prefer **string enums** for readability.
* Avoid **heterogeneous enums**.
* Use **`const enum`** for internal constants where runtime access is unnecessary.
* Consider string union types as a lightweight alternative:

```ts id="t1c5s8"
type Sugar = 1 | 2 | 3;
```

or

```ts id="3y6zml"
type ChaiType = "masala" | "ginger";
```
